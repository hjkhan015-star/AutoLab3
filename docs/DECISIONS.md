## Phase 6A slice 1 — Safety summary (B-027)
- **One shared mechanism, no per-page markup:** the summary is derived from the page's own Safety text (first clause, ≤ 90 characters; an `al-sec` can override it with `data-summary`), so wording cannot drift from the section. Two authoring forms are recognised because the pages use both.
- **Re-sync without a MutationObserver:** the Monitor rule forbids observers in `kit.js`, so pages that swap their description on a mode switch call `ui.panel.descChanged()` (a separate name, because the `remeasure` test counts calls on four pages).
- **App version left at 1.0.0** (release gate is Phase 7); module versions were patch-bumped because `kit.js` / `app.css` are shared.
- **Open for the owner:** the summary reads as the Safety section's first clause, which on a few pages is a statement of fact ("The line stays pressurised after the engine stops") rather than an instruction. A per-page `data-summary` can be added if you want imperative wording.

## Phase 6A slice 2 — touch targets (B-010)
- **Hit area, not size:** the pictures keep their size (the header is capped at 32 px by an existing test); a transparent pseudo-element reaches `--ctl-tap` on each axis and only grows when the control is smaller. 4 px of slack, because a neighbour can clip a couple of pixels.

## Phase 6A slice 3 — script CSP (B-011)
- **Hashes, not nonces:** the site is static, so a per-response nonce is not possible; hashes are computed at sync time from the files.
- **Kept the injected perf-guard as is** (hash of the exact injected text) instead of moving it to a file: a dynamically added external script runs asynchronously, and this guard has to be in place before the module starts its animation loop and audio.
- **`style-src` left alone:** removing `'unsafe-inline'` there means moving every inline `<style>` and `style=` attribute out (or hashing them with `'unsafe-hashes'`); it protects far less than the script half and touches every page. Open for the owner.

## Phase 6A slice 4 — one scale for spacing, type and motion
- **Spacing grid is 2 px, not 4.** The app really used 2 / 6 / 10 / 14 / 18 px (about 90 declarations), so the 4 px scale got five half steps (`--s-0h … --s-4h`) instead of forcing 2 px jumps. Odd values (3, 5, 7, 9, 11, 13 …) were rounded **down** to the grid, so a layout never grows from spacing. Per literal the change is ≤ 1 px.
- **Type scale of 11 steps** (10 · 11 · 12 · 13 · 14 · 16 · 18 · 20 · 22 · 26 · 32 px) replaces 22 distinct sizes (10.5, 11.5, 12.5, 13.5, 14.5, 15, 19 … were in use). Nearest step, ties **up** (never shrinks text); 8.5 / 9 / 9.5 px (four rules) go to 10 px, the smallest step. `--ctl-text` / `--ctl-value-text` keep their pinned values (11 / 12 px = `--fs-xs` / `--fs-sm`; a test checks they agree).
- **Motion:** every transition and one-shot entrance animation uses the three durations and three curves. 100–180 ms -> fast (150), 200–300 -> base (240), 350–500 -> slow (420); CSS `ease` / `ease-out` and two hand-written Béziers -> `--ease-out`; a transition with no curve gets `--ease-out`. Side effect worth having: these now collapse to 1 ms under `prefers-reduced-motion` (before, 48 literal durations ignored it unless the rule sat in a media query). Ambient loops (spinner, sheen, pulses, flow) and animations longer than .5 s are scenery and keep their own timing.
- **What stays literal:** 0, 1 px hairlines, negative optical margins, three named layout dimensions (22 px icon clearance in `controls.css`, the 96 px nav clearance on the home list, a 232 px side-readout gutter on `ecu--sensors`; each listed in the test with its reason), and `calc()` terms with safe-area insets.
- **Found:** `--fs-lg` was used (module-error title) but never defined; the rule now says `--fs-xl` (B-029).
- **Owner decisions delegated to Claude in this session** ("take the best decisions"): (1) portrait dock handle **20 -> 24 px** (meets WCAG 2.2 AA; slim state stays 12 px); (2) segmented buttons **stay at AA**; (3) B-004 / B-005 **deferred** (not defects; Phase 7 review); (4) Safety line wording **unchanged** (content decision on 24 pages; `data-summary` exists for overrides); (5) `style-src 'unsafe-inline'` **kept** (high churn, small gain for a static site). Each is reversible and recorded in `QA.md` "Known limits"; the owner can overrule any of them.
- **Not done on purpose:** `font:` shorthand and `letter-spacing` / `line-height` are not covered by the test (7 pages use `font:` shorthand, without px sizes in scope); inline `style=` is covered by nothing (one attribute exists).

## Phase 6A slice 5 — theme switch, state screens (motion measured first)
- **Measured before changing** (`motion5.py`, Chromium, shell + radiator module, Chromium's own metrics so the slow software canvas does not hide the result): open / close of a module start only transform / opacity animations (fine); a dock tap starts one `height` transition (~5-8 ms of layout); **a theme switch started 45 colour / border transitions at once** (17 in the shell, 28 in the module), several on blurred glass panels.
- **Theme switch = no transitions.** The theme classes change under `html.al-theme-swap` (`transition: none !important`, in the first CSS layer so it beats every later `!important`), with a forced style flush before the class is lifted — synchronous, so there is no timer that could leave the class on. Result: 45 -> 3 transitions (the 3 are the always-on ambient loops), style-recalc cost of a switch roughly halved. Alternative considered: a cross-fade with `document.startViewTransition` — Chromium-only and it snapshots the whole screen including the 3D canvas, i.e. exactly the full-screen cost this slice removes. An instant swap is what `prefers-reduced-motion` users get anyway.
- **Left as is, on purpose:** the dock `height` transition (the dock is fixed-position and `overflow: hidden`, so the layout is local; turning it into a transform would need the grid inside it to be rebuilt) and the `.ui-slot` position transition (small containers). The dock swipe is discrete (gesture -> state -> one transition); there is no finger-following drag, adding one is an interaction redesign, not polish.
- **One state pattern.** The module-error screen was the reference; the empty states (search, Recents) now use the same classes, so title size / colour, sub text, icon, spacing and the 44 px action button come from one definition (`.al-state*` in `core/app.css`). Visible change: empty-state title 16 px dim -> 18 px full-strength text (the error screen's). Loading stays the shared `.boot-ring` (start-up and module open). Not unified: `guard.js` and `404.html` keep their own inline hex colours, because they must work when the stylesheet did not load.
- **Found while verifying:** none new. (Mutation check: removing the class-clear from `kit.js` makes `states.test.mjs` fail.)

## Phase 6A slice 6 — first paint, touch
- **First paint, measured** (`firstpaint6.py`, Chromium, slow-4G 1.6 Mbps / 150 ms RTT, 4x CPU, fresh profile, median of 3). The shell had three static `modulepreload` tags (1.3 MB of three.js) in `<head>`. Current: first paint 2.4 s, home cards 4.0 s, first module ready 6.4 s (tap 1.5 s after the cards). No preload: 1.7 s / 2.8 s / 10.4 s. `fetchpriority="low"` on the same tags: no change (2.4 / 4.1 / 6.5). **Deferred injection (after `load`, on idle, 4 s timeout): 1.7 s / 2.8 s / 8.6 s, and after 8 s of browsing 3.7 s vs 3.5 s for the static tags.** Chosen: deferred. Trade-off, stated plainly: the shell is ~0.7 s faster to first paint and ~1.2 s faster to its cards on every first visit; the cost is a first module opened within ~1.5 s of the home screen appearing (about 2 s slower on a slow link). A returning visitor is served by the service worker either way.
- **Measurement traps found (kept so nobody repeats them):** (1) disabling the browser cache makes a preload look like pure cost (the preloaded copy cannot be reused: it doubled the bytes); (2) Playwright **disables the cache whenever a `route` handler exists**, so variants must be real directories served directly, not rewritten through `route`.
- **Where it lives:** the warm-up script is generated by `tools/sync.mjs` between the `three-preload` markers (a CDN build keeps `preconnect` / `dns-prefetch`, and the same deferred loader with `crossorigin`). Not warmed on `navigator.connection.saveData` or a 2G type (1.3 MB is a real cost there). The inline script is covered by the CSP hash like every other.
- **Touch, measured with emulated touch + CDP:** the dock-handle swipe is not cancelled (`touch-action: none`, clean pointer events), a drag on the canvas does not scroll the page, shell scrollers already `overscroll-behavior: contain`. **Gaps fixed:** controls, 3D labels and the canvas were `user-select: auto` (a long press while orbiting can pop up a selection or the iOS callout over the scene) -> one rule in the reset layer; `html` had `overscroll-behavior: auto` (only `body` had `none`; the root scroller is what blocks pull-to-refresh) -> `none`; native `input[type=range]` (the options-sheet slider) -> `touch-action: pan-y`. Reading text stays selectable on purpose.
- **Not done:** lazy-loading heavy scene code inside a module (modules are single files; splitting them is a restructure, not polish), image / font work (no remote fonts or images exist), a real-device check of long-press and pull-to-refresh (Chromium emulates the events, not the iOS callout or Android refresh).
