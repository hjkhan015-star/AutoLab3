# Auto Lab v1.0.0 — Build Guide

How a module page is put together, how to add one, and the rules the tests enforce. **To change, replace, merge or retire modules see `UPDATING.md`.**
Reference tables (every control spec, every Monitor channel) are in `COMPONENTS.md`.
`npm test` fails on any rule marked **[test]**.

## 1. Layout

```
app/            everything that is served (publish this folder)
  index.html    the shell: module cards, search, install, header menu host, one iframe per open module
  sw.js         service worker — VERSION and CORE_ASSETS are GENERATED by tools/sync.mjs
  core/         the engine: kit, controls, dock, monitor, chrome, labels, components, guard (≤ 8 JS files)
                + registry.js / roadmap.js / icons.js (data) and app.css / controls.css / components.css
  shared/       model-*.js (pure maths: alignment, balancing, drivetrain, autodrive, messaging) and part-*.js (builders: pipe, signal, gear, canvas, alignment, balancing) used by ≥ 2 modules (a test that imports one counts)
  modules/      <system-id>--<module-id>.html + .js  — one pair per module, nothing else
  assets/       icons + the self-hosted three.js (three.module.js, orbit-controls.js, room-environment.js — lower-case names)
tools/          sync.mjs (derives everything derived) · new-module.mjs · import-module.mjs · fetch-three.mjs
tests/          run.mjs + one *.test.mjs per concern; known-failures.json
docs/           this guide, COMPONENTS, MODULE-MAP (generated), MONITOR-MAP, DECISIONS, PROGRESS, AUDIT, QA
```

| File (under `app/core/`) | Owns |
|---|---|
| `registry.js` | DOMAINS, SYSTEMS, MODULES, SUBMODULES; publishes `window.AUTO_*` for the shell and kit. Icons: `icons.js`; learning path: `roadmap.js`. |
| `app.css` | Reset, **tokens** (colours, spacing, type, the `--c-*` categorical palette, `--ink` / `--paper`), base layout. |
| `controls.css` | Dock, header, stage inset, control and Monitor styles. Tokens only. |
| `components.css` | Side-panel widgets (overview, faults, self-check). |
| `kit.js` | `buildScene`, `UI.create`, `wireBridge`, materials, label re-exports, `monitorRows`. |
| `chrome.js` | Header (`createHeader`), the ⋯ menu (`createMenu`), `chromeButton`, **and the one keymap** (`createKeyRouter`, `installKeys`). |
| `controls.js` | Every control primitive (axis, pedal, momentary, dial, choice, toggle, action): the pure logic and registry first, the DOM layer after. |
| `dock.js` | The control dock: layout, states, pages, swipe. |
| `monitor.js` | The Monitor: pure core (value, rows, traces, gauge, status, footer) first, the DOM layer after. |
| `labels.js` | 3D label system and the one label density (`getLabelDensity` / `setLabelDensity`). |
| `components.js` | `createGeoKit`, `Widgets`, and `runGuidedModule` (the guided pages). |
| `guard.js` | WebGL / import failure overlay; `<html data-no3d>` skips the WebGL check (sensors). |

A module page is a thin HTML file (head, import map, markup) plus `<name>.js` — the logic. The import map is one snippet stamped
into every page by `npm run sync`; never edit it by hand. The comment block at the top of each module `.js` is generated too.

## 2. The rules **[test]**

- **One place (R1).** Every control is one node, built by `controls.js`. A module never writes `<button>`, `<select>`, `type="range"` or `createElement('button')`; it declares a spec. Allowed to build controls: `controls.js`, `chrome.js`, `dock.js`, `monitor.js` (plus the shell `index.html`, `404.html`, and `guard.js`'s single Retry button).
- **One dock, one Monitor (R2).** Controls live in the dock, numbers live in the Monitor. A number is printed once. The dock is 24 vh by default and never above 30 vh; the info sheet is at most 50 vh.
- **Tokens only (R3).** No hex / `rgb()` / `rgba()` in any `<style>` or stylesheet except the per-module `--al-accent` declaration. Use `var(--text)`, `var(--c-cyan)`, `color-mix(in oklch, var(--c-red) 20%, transparent)`, `var(--ink)` / `var(--paper)`. A token adapts to the light theme, so a module needs no `html.light-theme` colour overrides. (3D materials in JS are not CSS and keep their own colours. `404.html` loads no stylesheet and is exempt.)
- **One scale for size and motion (R3b).** `padding` / `margin` / `gap` use `var(--s-*)` (2 px grid: `--s-0h` 2, `--s-1` 4, `--s-1h` 6, `--s-2` 8, `--s-2h` 10, `--s-3` 12, `--s-3h` 14, `--s-4` 16, `--s-4h` 18, `--s-5` 20, `--s-6` 24, `--s-8` 32, `--s-10` 40); `font-size` uses `var(--fs-*)` (`2xs` 10 · `xs` 11 · `sm` 12 · `md` 13 · `base` 14 · `lg` 16 · `xl` 18 · `2xl` 20 · `3xl` 22 · `4xl` 26 · `5xl` 32); `transition` / one-shot `animation` use `var(--dur-fast|base|slow)` (150 / 240 / 420 ms, 1 ms under reduced motion) and `var(--ease-out|in-out|spring)`. 0, a 1 px hairline and negative optical offsets are allowed; ambient loops (`infinite`) are exempt. `tests/tokens.test.mjs` fails on a literal.
- **Theme switch and state screens (R3c).** A theme change toggles `light-theme` under `html.al-theme-swap` (set, change, flush styles, clear — in one task; `kit.js` `applyTheme`, shell `applyShellTheme`), so no colour transition runs between themes; never add a timer or a per-element colour animation to it. Never `transition: all`, never animate `backdrop-filter` / `filter`. An error or empty screen is the shared `.al-state` pattern (`.al-state-icon / -title / -sub / -actions / -btn`, defined once in `core/app.css`); loading is the shared `.boot-ring`. `tests/states.test.mjs` pins all of it.
- **Start-up and touch (R3d).** The shell's `<head>` stays light: no static `<link rel="modulepreload">`, no classic `<script src>`, two stylesheets. three.js is warmed by the deferred loader that `tools/sync.mjs` writes between the `three-preload` markers (idle, 4 s timeout, off on Save-Data / 2G); change it in `sync.mjs`, never by hand. Buttons, role=button / tab / switch / slider, `summary`, `canvas`, `.label3d` and the dock handle are `user-select: none` with no iOS callout (reset layer of `app.css`); reading text stays selectable; the root has `overscroll-behavior: none`; a native range is `touch-action: pan-y`; custom drag surfaces are `touch-action: none` (R8). `tests/startup.test.mjs` pins it.
- **3D stage (R3e).** Label band: `bandFromObstacles` (`labels.js`) — only UI that overlaps the stage horizontally narrows it. Camera: `attachResize` refits the camera distance to the real stage (`fitModel` in `kit.js`, maths `frameScale` in `dock.js`); mark scenery meshes `userData.__noFrame`, or pass `buildScene({ frame: false })` for a module that moves its own camera. `tests/scene.test.mjs` pins it.
- **One registry (R4).** Control values live in the shared registry as 0..1. Read with `ui.controls.get / value / on`; never read a slider's DOM value.
- **One keymap (R5, R6).** `chrome.js` (the key router). Each key has one owner; the other side forwards.
- **Touch (R8).** `touch-action: none` and `contextmenu` blocking only on a control's drag surface.
- **Unique ids (R9).** A duplicate control id throws; a duplicate `id="…"` in a page fails the check; a page may not define `btn-play`, `btn-reset`, `speed` or `toolbar-extras`.
- **Layering (R10).** `z-index` only from the scale in `controls.css`.
- **No globals.** No `window.__*` anywhere. Shared state lives in a module (`labels.js` for label density).
- **No charts in panels.** No `<canvas>` or `<svg>` chart inside a panel / widget template; no writes to `ui.monitor.root`; a `ui.stage` canvas is never appended to the dock, panel or Monitor.
- **Precache.** `sw.js` `CORE_ASSETS` is generated from the files in `app/` (`npm run sync`); a test fails if it is stale.
- **One version.** `package.json` is the only place a version is typed. `npm run sync` stamps `sw.js` `VERSION`, README, this guide, COMPONENTS and the `components.*` headers.

## 3. Add a guided module (the usual case)

1. `npm run new-module -- <system-id> <module-id> --guided --stage <stage-id>` creates the pair, the registry entry (draft), an icon, the roadmap slot and a test stub, and runs `sync` (details: `UPDATING.md` recipe C). Then edit `modules/<system-id>--<module-id>.js`.
2. Fill `CFG` (fields in `COMPONENTS.md`, "Guided CFG"): `moduleId`, `title`, `kicker`, `accent`, `badge`, `camPos`, `target`, `floorY`, `chipLabel` (the Monitor's big value), `rows` / `ro` (Monitor rows), `legend` (colour tokens), `overview`, `faults`, `quiz`.
3. Controls: `ctl: { label, val, caption }` gives one 0–100 % axis (id `ctl`, read as `k`). For more, set `CFG.ctls = [axis specs]` (use presets) and `CFG.options = [choice | toggle | action specs]`. Use `onChange` to write to a variable your `build()` reads.
4. Write `function build(H)` returning `{ labels, update(c) }`. `update({ t, dt, k, sp })` returns what to show: `{ big, unit, bar, rows, ro, status: [text, on], ctl, traces }`. A time series is a Monitor trace: `CFG.traces = [{ id, label, min, max, length, series: [{ id, label, color: 'var(--c-cyan)' }] }]`, and `update` returns `traces: { id: [v…] }` (a sample only when one is due; `null` clears it on Reset).
5. End the script with `runGuidedModule(CFG, build)`.
6. The tool already registered it; add it to its system's `flow` / `related` where it belongs, fill the manual QA cells, then promote `draft` → `stable` (`UPDATING.md` recipe C).

## 4. Add a custom module (own scene and update loop)

`npm run new-module -- <system-id> <module-id> --stage <stage-id>` (without `--guided`) creates a working skeleton — a block, one axis, one Monitor value, play / reset — and registers it; the sketch below shows the pieces you replace it with.

```js
import * as Base from '../core/kit.js';
const state = Base.createUIState();
const { scene, camera, renderer, controls, viewManager } = Base.buildScene({ camPos: [4, 2, 6] });
const ui = Base.UI.create({
  moduleId: 'mymodule',
  panel:   { kicker: 'Engine', title: 'My module', tabs: [{ id: 'overview', label: 'Overview' }], badge: { text: 'Badge' } },
  monitor: { config: { label: 'Boost', value: { label: 'Boost', unit: ' kPa', max: 200, bar: true },
                       rows: [['rpm', 'Speed'], ['temp', 'Temp']], traces: [], status: { text: 'Running' } },
             initial: { value: { text: '0', unit: ' kPa', bar: 0 }, status: ['Running', false] } },
  toolbar: { play: true, reset: true, speed: { label: 'Sim speed', min: 0.15, max: 2.5, step: 0.05, value: 0.85 }, labels: true },
  axes:    [{ id: 'rpm', preset: 'rpm', side: 'left' }, { id: 'load', preset: 'load', side: 'right' }],
  options: [{ id: 'mode', type: 'choice', layout: 'segmented', label: 'Mode', def: 'a', options: ['a', 'b'] }]
});
const bridge = ui.wireBridge({ viewManager, state, onCommand: (d) => { if (d.action === 'reset') ui.controls.resetAll(); } });
bridge.ready();
// each frame
ui.monitor.update({ value: { text: '120', unit: ' kPa', bar: 60 }, rows: { rpm: '2800 rpm', temp: ['96 °C', 'warn'] }, status: ['Running', true] });
const rpm = ui.controls.value('rpm');           // real value, step-snapped
const mode = ui.controls.value('mode');         // option id
```

- **The dock** is configured through `UI.create({ toolbar, axes, options, widgets })`; later additions go through `ui.addOptions([...])` or, for a node you built, `ui.toolbar.dock.addOption(node)` / `addPrimary({ id, side, node })` then `ui.toolbar.dock.refresh()`. There is no `ui.dock.set`. Read controls with `ui.controls.get(id)` (0..1), `.value(id)`, `.on(id, fn)`, `.set(id, n)`, `.resetAll()`; `ui.axis(id)` returns the instance.
- **The Monitor** is `ui.monitor.set(config)` (rebuilds rows / traces / footer, e.g. on a mode switch) and `ui.monitor.update(patch)` (values: `rows`, `rowLabels`, `traces`, `gauge`, `footer`, `status`). Text is written at ≤ 9 Hz, traces drawn at ≤ 30 Hz, so call `update` every frame.
- **`monitorRows(ui, ids, drop)`** lets old code that writes `ro.x.textContent = …` / `ro.x.className = 'v warn'` write Monitor rows instead.
- **A picture that is not a time series** (spectrum, advance curve, torque map): `const cv = ui.stage.canvas({ id, label, width, height, corner: 'bl' | 'br', size })`, draw into `cv`, change its caption with `ui.stage.caption(id, text)`, remove with `ui.stage.remove(id)`. It floats over the stage, above the dock, with no pointer events.
- **A 2D page** (no 3D scene): add `data-no3d` to `<html>`, link `app.css` and `controls.css`, set `body { padding: var(--stage-top) var(--dock-rail) calc(var(--dock-h) + var(--safe-b)) }`, and give the ⋯ menu `menuHide: ['density', 'wireframe', 'xray']` in `wireBridge`. `data-no3d` also makes `kit.js` skip three.js, so such a page needs no import map and loads offline on a first visit. Inside the shell the module reports `menuHide` in its `ready` message and the shell hides those rows (and ignores W / X) while that module is open. `ecu--sensors.html` is the example.

## 5. Keymap **[test]**

| Key | Action | Owner |
|---|---|---|
| Space | play / pause | module (the shell forwards it) |
| R | reset | module |
| D | label density | module |
| L | theme | shell |
| W | wireframe | shell |
| X | x-ray | shell |
| Esc | close the ⋯ menu / go back | shell |
| ← → ↑ ↓ and Shift | adjust the focused control; Shift-hold drives a pedal | the control |

Keys are ignored while typing in an input / select, with Ctrl / Meta / Alt held, and Space on a focused button, link or slider means "activate".

## 6. Mobile budget

- Header: one row, **32 px** (28 px on a landscape phone). Standalone only; embedded modules have no header of their own.
- Dock: default **24 vh**, hard ceiling **30 vh**; slim state 56 px; options row 44 px; landscape phones use two 140 px side rails. Tap targets are at least `--ctl-tap` (44 px).
- Wide screens (**1024 px and up**, not a phone): no bottom bar. Controls live in a **left rail** (280 px, 320 px from 1600 px, scrolls if long), the Monitor is the **right column**, and the model uses the middle at full height. The ‹ handle folds the rail to a 56 px strip (saved per module). 721 - 1023 px keeps the one-row bottom bar.
- Info panel: a bottom sheet of at most 50 vh on phones (closed by default, opened by ⓘ); a side panel on desktop.
- Monitor: a 28 px strip under the header on phones, a card at the top right from 721 px, the right column from 1024 px (never folded to an orb there). Keep the row list short enough to read at a glance (the longest today are crankshaft-piston with 17 and mpfi / lubrication with 11; QA.md tracks them).
- The model sits in the upper / middle of the stage (`--stage-top` to `--dock-h`). A stage canvas must not cover it.
- Motion respects `prefers-reduced-motion`.
- Offline: after the first visit everything (including three.js) is served from the cache.

## 7. Presets

`rpm` (800–5000, 1800), `load` (0–100 %), `ambient` (−10–45 °C), `vehicle-speed` (0–160 km/h), `voltage` (8–15 V), `percent` (0–100). Any field can be overridden: `{ preset: 'rpm', min: 0, max: 7000, def: 0 }`.

## 8. Release checklist

See `UPDATING.md` recipe H (version rules in its section 2). In short: `npm run sync -- --check` and `npm test` green with nothing skipped; module versions and `package.json` bumped (the only place a version is typed — `sync` stamps `sw.js`, README and QA); CHANGELOG line; QA cells for what changed.

## 10. The shell ⇄ module protocol (`postMessage`)

The shell (`index.html`) shows one module per `<iframe>`; both are served from the same origin. They talk with `window.postMessage`, and **every
receiver checks who sent the message** (`shared/model-messaging.js`, tests in `tests/model-messaging.test.mjs`):

- a module accepts a message only if `event.source === window.parent` **and** `event.origin === location.origin` (`trustedFromParent`);
- the shell accepts a message only from the window of one of *its own* iframes on its own origin (`trustedFromFrame`);
- messages are sent to `location.origin`, never `'*'` (`targetOrigin`; a page opened from `file://` has the opaque origin `"null"` — the only case that falls back to `'*'`, and the source check still applies);
- a page that is not embedded (`window.parent === window`) trusts nobody.

A static test fails the build for any new `message` listener without such a check and any `postMessage(…, '*')`.

| Direction | Shape | Meaning |
|---|---|---|
| shell → module | `{ source: 'auto-shell', moduleId, type: 'command', action, value }` | `setPlaying`, `setSpeed`, `setTheme`, `setWireframe`, `setXRay`, `setLabelDensity`, `setGas`, `toggleInfo`, `reset`, `key` |
| module → shell | `{ source: 'auto-module', moduleId, type: 'ready', menuHide }` | the page is built: the shell reveals the frame and hides the listed ⋯ menu rows |
| module → shell | `{ source: 'auto-module', moduleId, type: 'state', playing \| density \| status }` | keeps the shell header and menu in step |
| module → shell | `{ source: 'auto-module', moduleId, type: 'key', action }` | a key the module does not own (the one keymap, `chrome.js`) |
| shell → module | `{ source: 'auto-shell', action: 'perf-pause' \| 'perf-resume' }` | the shell's background-tab saver (injected into the iframe) |
| module → shell | `{ source: 'auto-module-perf', action: 'perf-ready' }` | the saver is installed |

Add a new command by adding it to `defaultHandlers` in `kit.js` and a sender in `index.html`; both sides get the origin check for free as long as
they use the helper. Old links keep working: `index.html#<old-id>` goes through `resolveModule` (registry `replacedBy`).
